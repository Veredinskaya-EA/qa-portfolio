# Практические задания по теме 5 «Основы баз данных и SQL»

> **Инструменты:** SQLiteStudio / PostgreSQL, DBeaver

**Соглашение о результатах:** в каждом задании приведён ожидаемый результат на эталонных данных из методички. Фактический результат выполнения проверен на своих данных; рядом с результатом оставлено место для скриншота.

## Задание 1. Создание базы данных и таблицы

**Цель:** научиться создавать новую базу данных и таблицу.

**Запрос:**

```sql
CREATE TABLE customers (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(100)
);
```

**Проверка структуры таблицы:**

```sql
DESCRIBE customers;
```

**Результат:** таблица `customers` создана с тремя столбцами: `id` (целое число, первичный ключ), `name` (строка до 100 символов), `email` (строка до 100 символов). Команда `DESCRIBE` выводит список столбцов с их типами; для `id` видно `PRIMARY KEY`.

*(скриншот: результат DESCRIBE customers)*

## Задание 2. Вставка данных в таблицу

**Цель:** научиться добавлять данные.

**Запрос:**

```sql
INSERT INTO customers VALUES (1, 'Анна', 'anna@mail.com');
INSERT INTO customers VALUES (2, 'Иван', 'ivan@mail.com');
INSERT INTO customers VALUES (3, 'Олег', 'oleg@mail.com');
```

**Результат:** в таблице `customers` три строки:

| id | name | email |
|----|------|----------------|
| 1 | Анна | anna@mail.com |
| 2 | Иван | ivan@mail.com |
| 3 | Олег | oleg@mail.com |

*(скриншот: SELECT * FROM customers после вставки)*

## Задание 3. Извлечение данных (SELECT)

**Цель:** освоить базовые выборки.

**Запрос:**

```sql
SELECT * FROM customers;
```

```sql
SELECT name FROM customers;
```

**Результат:**

Первая команда возвращает все столбцы всех строк. Вторая — только столбец `name`:

| name |
|------|
| Анна |
| Иван |
| Олег |

## Задание 4. Обновление данных (UPDATE)

**Цель:** обновить данные в таблице.

**Запрос:**

```sql
UPDATE customers
SET email = 'newemail@mail.com'
WHERE id = 2;
```

**Результат:** у клиента с `id = 2` (Иван) адрес электронной почты изменён на `newemail@mail.com`. Остальные строки не затронуты — благодаря условию `WHERE`.

> **Примечание (важно для тестировщика):** если выполнить `UPDATE` без `WHERE`, изменятся **все** строки таблицы. Перед обновлением условие полезно проверять через `SELECT` с тем же `WHERE`.

---

## Задание 5. Удаление записи (DELETE)

**Цель:** удалить конкретную строку.

**Запрос:**

```sql
DELETE FROM customers WHERE id = 3;
```

**Результат:** удалена строка Олега (`id = 3`). В таблице остались Анна и Иван.

> **Примечание:** `DELETE` без `WHERE` очищает всю таблицу. Опасная операция, всегда проверяем условие.

## Задание 6. Добавление внешнего ключа


**Результат:** таблица `orders` создана. Столбец `customer_id` связан с `customers(id)`: база не позволит вставить заказ для несуществующего клиента (контроль ссылочной целостности).

## Задание 7. Использование JOIN для объединения данных

```sql
SELECT customers.name, orders.amount
```

## Задание 8. Агрегация данных (SUM, AVG)

**Цель:** подсчитать общую сумму и средний чек заказов.

**Запрос:**

```sql

SELECT AVG(amount) AS average_order FROM orders;
```

**Результат:**

| total_sales | average_order |
|-------------|---------------|
| 4250.50 | 2125.25 |

*(сумма 2500.00 + 1750.50 = 4250.50; среднее 4250.50 / 2 = 2125.25)*

## Задание 9. Использование GROUP BY

**Цель:** сгруппировать заказы по клиентам.

**Запрос:**

```sql

FROM orders
```

**Результат:**

|-------------|-------------|

| 2 | 1 |

Если у одного клиента несколько заказов, они объединяются в одну группу, и `COUNT(*)` покажет их количество.

## Задание 10. Создание представления (VIEW)

**Запрос:**

```sql

JOIN orders ON customers.id = orders.customer_id;
```

**Проверка представления:**

```sql
SELECT * FROM customer_orders;
```

**Результат:** представление `customer_orders` создано и возвращает те же данные, что и запрос с `JOIN`. Представление не хранит данные само — оно выполняет запрос при каждом обращении.

## Задание 14. Использование BETWEEN и IN

**Цель:** использовать расширенные фильтры.

**Запрос:**

```sql
SELECT * FROM orders WHERE amount BETWEEN 1000 AND 3000;
```

```sql
SELECT * FROM customers WHERE id IN (1, 2);
```

**Результат:** первый запрос возвращает заказы с суммой от 1000 до 3000 включительно (обе границы входят в диапазон). Второй — клиентов с `id` 1 и 2. `IN` — компактная замена цепочки условий `id = 1 OR id = 2`.

## Задание 17. Проверка ссылочной целостности вручную

**Цель:** найти несвязанные записи.

**Запрос:**

```sql
SELECT * FROM orders
WHERE customer_id NOT IN (SELECT id FROM customers);
```

**Результат:** запрос возвращает заказы, у которых `customer_id` не встречается в таблице клиентов. Если внешние ключи работают корректно — результат **пустой**: «висячих» ссылок нет. Если вручную удалить клиента, у которого есть заказы (при отсутствии внешнего ключа), этот запрос их обнаружит.

> **Примечание:** это готовый шаблон проверки целостности данных — на собеседовании его часто называют при ответе на вопрос «как вы проверяете данные в БД».

## Задание 25. Обновление нескольких строк

**Цель:** массово изменить данные.

**Запрос:**

```sql
UPDATE orders SET status = 'в процессе' WHERE status IS NULL;
```

**Результат:** всем заказам без статуса присвоен статус «в процессе». Важная деталь: в SQL сравнение с `NULL` через `=` **не работает** (`status = NULL` не найдёт ни одной строки) — для проверки на отсутствие значения используется `IS NULL`.

## Задание 26. Использование CHECK-ограничения

**Цель:** ограничить допустимые значения.

**Запрос:**

```sql
CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT CHECK (age >= 18)
);
```

**Результат:** таблица `employees` создана с ограничением: возраст сотрудника не может быть меньше 18. Проверка ограничения (негативный тест):

```sql
INSERT INTO employees VALUES (1, 'Анна', 17);   -- ошибка: нарушен CHECK
INSERT INTO employees VALUES (1, 'Анна', 18);   -- успешно
```

Вставка со значением 17 отклоняется с ошибкой ограничения, вставка со значением 18 проходит — граница диапазона проверена с обеих сторон.

## Задание 28. Использование HAVING для фильтрации групп

**Цель:** отфильтровать результаты после группировки.

**Запрос:**

```sql
SELECT customer_id, SUM(amount) AS total_amount
FROM orders
GROUP BY customer_id
HAVING SUM(amount) > 3000;
```

**Результат:** при эталонных данных (2500.00 и 1750.50) запрос возвращает пустой результат — ни один клиент не набрал сумму больше 3000. После добавления второго заказа клиенту (например, `INSERT INTO orders VALUES (103, 1, 1200.00, NULL)`) в выборке появляется клиент 1 с суммой 3700.00.

> **Примечание:** `HAVING` фильтрует группы **после** агрегации, `WHERE` — строки **до**. В `WHERE` агрегатные функции использовать нельзя — это частый вопрос на собеседовании.
