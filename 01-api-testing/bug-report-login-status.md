# BUG-REPORT

## Заголовок
Неверный статус-код при авторизации с некорректным паролем: 200 OK вместо 401 Unauthorized

## Серьёзность (Severity)
Major

## Приоритет
Высокий

## Окружение
- Сайт: https://demoqa.com/login
- API-эндпоинт: POST https://demoqa.com/Account/v1/Login
- Инструменты: Google Chrome (DevTools, вкладка Network), Postman

## Предусловие
Пользователь зарегистрирован на demoqa.com (тестовый аккаунт: логин заменён на заглушку).

## Шаги воспроизведения
1. Открыть https://demoqa.com/login
2. Ввести корректный логин
3. Ввести НЕВЕРНЫЙ пароль
4. Нажать кнопку "Login"
5. В DevTools (вкладка Network) найти запрос к /Account/v1/Login и проверить статус ответа

## Пример запроса (Postman)
POST https://demoqa.com/Account/v1/Login
Content-Type: application/json

{
  "userName": "********",
  "password": "********"
}

## Ожидаемый результат (Expected)
Статус ответа сервера — 401 Unauthorized, тело ответа содержит сообщение об ошибке.
На странице отображается сообщение "Неверное имя пользователя или пароль!".

## Фактический результат (Actual)
На странице отображается сообщение "Неверное имя пользователя или пароль!" (UI корректен),
но статус ответа сервера — 200 OK.

## Комментарий / возможное влияние
Фронтенд в данном случае полагается на текст сообщения, а не на код статуса.
Системы мониторинга, логирования и интеграции, ориентированные на HTTP-статусы,
будут считать попытку авторизации успешной. Возможны ложные метрики "успешных входов"
и проблемы при интеграции со сторонними системами, использующими стандартную семантику
HTTP-кодов.

## Приложения
Скриншот 1: запрос и ответ в DevTools (Network) — статус 200 OK при неверном пароле.
Скриншот 2: тот же запрос в Postman — статус 200 OK, тело ответа.
